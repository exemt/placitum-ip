# Placitum ip

[English](README.md) · Русский

Инспектор адреса Placitum. Решает по клиентскому адресу: сам адрес, его подсеть, страна и
автономная система, плюс динамические списки, которые меняются на ходу.

Самый дешёвый инспектор и обычно первый на волне: отвечает за доли миллисекунды и отсекает то, что
незачем показывать дорогим проверкам. Ни заголовков, ни тела он не читает и работает только на
фазе запроса.

```
модуль ──► waf.req.ip ──►  ip  ──► allow | deny
                            │
                            ├── профиль: правила над наборами адресов
                            └── живые наборы: зеркало keeper, обновления по шине
```

## Наборы

Набор — именованное выражение над сырьём: списки адресов, динамические списки, страны и автономные
системы, минус исключения. Он говорит, кто это, и ничего не решает.

```yaml
# sets.yaml
office:
  lists: [office]                # lists/office.txt
  exclude: { countries: [ru] }
datacenters:
  live: [7b1d0a44-…]             # динамический набор из live.yaml
  asns: [14061, 16509]
not-ru:
  countries: [ru]
  inverse: true                  # всё, кроме получившегося
```

`exclude` принимает те же четыре блока и вычитается из объединения; `inverse` применяется после
вычитания. Вложенности нет. Пустой набор роняет загрузку: он не совпадает ни с чем, а его `inverse`
совпадает со всем.

## Профили

Профиль выбирается тегом маршрута `route.profile`; пустой тег означает `default`, и без профиля
`default` процесс не стартует.

```yaml
# profiles/default.yaml
rules:
  - set: office
    action: allow
  - set: datacenters
    action: deny
    response: blocked
  - dataset: tor
    action: request
    to: captcha
    do: challenge
    code: IP_GREYLIST
  - dataset: office
    not: true
    action: list
    list: suspects-uuid
    write: net
    ttl: 10m
default: allow
outcomes:
  - on: black
    list: banned-uuid
    write: asn
    ttl: 1h
    code: AUTO_BAN
```

Вердикт выносится в три шага:

1. **Белые строки** смотрятся первыми, где бы ни стояли: совпадение сразу даёт `allow`. Исключение
   обязано побеждать запрет при любом порядке строк.
2. **Чёрные строки** — сверху вниз, первая совпавшая даёт `deny`. `response` называет запись
   страницы блокировки (по умолчанию `blocked`), `code` — причина.
3. **`default`** отвечает, когда не совпало ничего: `allow` (умолчание) или `deny`.

Счёта нет: вердикт один из двух.

**Строки `request` и `list`** ничего не решают и работают при любом вердикте, в том числе на белом:
«этот адрес наш, будь мягче» — высказывание именно про белый список. Они спрашивают сырой список
(`dataset`), а не набор, и `not: true` срабатывает, когда адреса в нём нет.

- `request` кладёт в ответ сигнал соседу: `to`, глагол `do` из канала действий, `apply`, `code`,
  `delta` или `value`. После `deny` фаза заканчивается, и поздние волны её не увидят; глаголы записи
  `mark`, `audit` и `archive` исполняет модуль, и они работают всегда.
- `list` вносит адрес в динамический набор из `live.yaml` на `ttl` (`300`, `5m`, `1h`, `1d`). `write` говорит,
  кого писать: адрес (`addr`, умолчание), его эффективный анонс (`net`), все анонсы над ним, включая
  более широкие анонсы других систем (`net_all`), или автономную систему целиком (`asn`).

**Строки по исходу** (`outcomes`) делают то же самое и срабатывают по тому, где оказался адрес:
`white` (совпала белая строка), `black` (совпала чёрная) или `none` (ответил `default`). `overload`
срабатывает на собственной очереди инспектора: с `at` (25–100) — когда очередь заполнена на `at`
процентов, без него — только когда запрос сброшен.

Когда проверить не удалось, инспектор отвечает `error`, и исход выбирает `waf_exception` маршрута:

| Код | Почему |
| --- | --- |
| `IP_UNKNOWN_PROFILE` | маршрут называет профиль, которого нет |
| `IP_MALFORMED` | адрес клиента пуст или не разбирается |
| `IP_MISSING_SET` | набор или список, названный профилем, не дошёл |
| `IP_GEO_UNAVAILABLE` | записи `net`, `net_all` или `asn` нужен кодер гео, а он не отвечает |

## Откуда данные

| Что | Откуда | Когда меняется |
| --- | --- | --- |
| профили, наборы, статические списки, страны, префиксы систем | поколение контроллера | с новым поколением |
| живые наборы | keeper, `waf.sets.<имя>` | сразу, без поколения |

В образе лежит только то, что установка не даёт удалить в панели: профиль `default` без правил и
пустые пресеты `default_allowlist` и `default_blocklist`. Поколение подменяет это дерево целиком:

```
lists/<имя>.txt         статические списки: префикс или адрес на строку, # — комментарий
asns/<номер>.txt        префиксы автономных систем
geo/<код>/              диапазоны стран
sets.yaml               наборы
live.yaml               живые наборы: uuid: имя
profiles/<имя>.yaml     профили
```

В поколении имена файлов — uuid; дерево, написанное руками, с человеческими именами читает тот же
код. Ошибка чтения оставляет действующий снимок, а правило с неизвестным набором роняет загрузку
целиком: половина политики хуже старой.

**Живые наборы** (списки, отмеченные в панели активными) в поколении не уходят: там только их uuid и
имя. Состав держит keeper, инспектор его зеркалит: уведомления по `waf.sets.<имя>`, пакеты изменений
и снапшоты из внутреннего Redis, сверка хеша на каждом шаге. Бан, поставленный соседом, действует
здесь через миллисекунды. Непрогретый набор — промах, а не блокировка: не дошедший список не имеет права
закрыть маршрут. Записи `list` уходят в keeper после ответа, так что несостоявшаяся запись не стоит
вердикта.

## В аудите

Коды находок между версиями не меняются, потому что по ним строят исключения: `ip-denylist`,
`ip-geo`, `ip-unknown-profile`, `ip-malformed-address`, `ip-missing-set`. Секция `engine` события
инспектора называет поколение (`gen`), позицию правила (`rule`), набор (`set`) и что совпало
(`match`: `list`, `live`, `country`, `asn`, `inverse`). Отказ ещё и говорит клиенту, что закрыто: адрес, сеть,
страна или система попадают на страницу блокировки.

Проба в образе шлёт настоящее сообщение по шине:

```sh
ip-probe --client-ip 203.0.113.10 --profile default --expect allow
```

Что нужно рядом и все настройки — в [INSTALL.ru.md](INSTALL.ru.md).
